# Lab UI 方案自审与修订

日期：2026-09-29。对象：[初版研究](README.md)。状态：研究修订，未获设计定稿或开发授权。

**结论：问题诊断成立，原方案还不能直接作为开发规格。最需要收回的是把快速试用与进入单实验工作台绑定；保留“页面内可操作的实验＋可选专注放大”更合适。** 可调目录、可调详情、滚轮隔离都值得继续研究，但尚不能据此认定新界面已经更好看、更好用。

本次复查初版文本、当前组件的输入与生命周期、目录与哈希实现，并核对 React 和 Google Maps 官方文档。尺寸沿用初版的本地浏览器测量；没有重新做触屏、触控板或候选原型测试。以下区分已见事实、风险推断与修订建议。

## 1. 会改变方案方向的问题

### 1.1 优先修订：进入工作台不应成为快速试用的前置条件

初版 §4 把总览写成“较大预览＋展开操作入口”，§6 又把浏览态能否直接拖转留待决定。这会使多台连续比较变成反复进入、退出。本站 Lab 同时承担作品集证据与直接体验；目前没有用户研究证明读者愿意先进入一个工具界面。

更重要的是，**禁止画布吞普通滚轮，不必同时禁止拖转、拖关节或点击参数。** Google Maps 的 cooperative 示例允许正常翻页并提供缩放按钮，支持的是“把页面滚动与模型操作区分开”，并不能证明本站必须增加完整工作台。[官方交互文档](https://developers.google.com/maps/documentation/javascript/interaction)

修订：桌面仍可在长页直接拖动、调参数；普通滚轮经过画布时滚页面。支持相机缩放的台架增加明确的缩放与归位入口，需要大画面或连续滚轮缩放时再“放大操作”。放大承担扩大空间和明确输入归属两件事；不承担重新建立实验目录、缓存多个工作台状态等额外职责。

手机上的单指滑页与直接拖模型确有冲突，不能照搬桌面规则。候选是普通页单指滑动浏览，显式放大后再启用模型拖动；这仍需实机验证，也不代表现有相机已经支持所有双指手势。

### 1.2 优先修订：“三个框都可调”尚未说明谁控制谁

目录属于整页，详情属于单台，画布还包含各台自己的操作区。若 17 台各有独立详情宽度和独立拖拽边界，长页的对齐与后续维护都会复杂；若只有一个全局详情区，又会回到单实验切换与状态保存问题。

修订候选：目录使用全页宽度偏好；桌面详情列先共用一个宽度偏好，每台可以单独展开或收起；画布占剩余空间。目录收起后提供清楚的“目录”入口，不预设一定保留 56px 窄栏——初版还没有解释这条窄栏装什么、如何识别 17 台实验。

收起／恢复是基本操作，连续拖宽是补充。宽度必须受画布、文字换行和可用高度共同约束。窄屏改上下组织，不把三个框一起缩小。

### 1.3 优先修订：说明与操作参数不能混装进一个可消失的详情栏

初版流程图把“参数／说明／规格”放到同一右栏，虽然正文提过区分常用操作，但边界不够清楚。关闭详情后，读者不应失去调节当前实验的主要按钮。

当前 `TentacleBench`、`SkinLayersBench` 等把参数、回调和控件放在组件内部。把这些全部搬进一个通用外侧栏，会涉及多台组件接口调整，不能称作简单改外框。

修订：说明与完整规格可以折叠；主要实验参数和视角操作留在台架内，沿用已有“解什么／怎么看”的分组。高级参数是否收纳，逐类台架决定。目标几何、实际求解结果、失败状态等用于判断画面含义的信息必须留在可见位置，不能因精简 HUD 被一起隐藏。

## 2. 原方案低估的落地约束

### 2.1 加宽有收益，但宽度图不能证明模型显示更大

初版已经提醒高度限制，但没有把它变成具体的布局验收条件。用初版 840px 画布宽度作一次压力估算：

```text
画布仍按 700:520：840 × 520 / 700 ≈ 624px 高
若复杂控制区仍需 173px，再预留 96px 标题、边距与退出入口：
624 + 173 + 96 ≈ 893px
```

其中 173px 来自原现状测量，96px 是压力估算的假设，893px 不是候选原型实测。它说明：在 768px 高的笔记本上，单纯横向加宽会把控制区推出视口。若保持全部画面可见并预留同样空间，画布仅余约 499px 高；保留原比例时宽约 672px，“中栏宽 840px”不再等于模型实际占宽。

修订：下一版必须同时设计舞台高度、主要控制区高度与剩余空间。允许复杂台架拥有独立布局，但不能靠裁掉关键模型或缩小控件字体达成。多层台的 700:440 主视图及正投影也要单独处理。初版的 720／640px 下限、宽度交互图只作为试值和空间算术，不作为可用性或视觉通过证据。

### 2.2 “复用同一个组件”不等于“展开后保留同一实验状态”

当前触手的相机、求解状态在初始化 effect 与闭包中，初始化 effect 依赖 `spin`；多层目标台的相机也在初始化 effect 内。展开时换父节点、条件渲染另一份组件，或让展示模式改动初始化依赖，都可能重新初始化。

React 按渲染树中的位置保留状态；仅使用同名组件或相同 key，不能跨不同父树保证延续。Portal 更新时更换目标 DOM 节点也会重建其内容。[状态保留](https://react.dev/learn/preserving-and-resetting-state) / [Portal 参数说明](https://react.dev/reference/react-dom/createPortal)

修订：优先验证维持原挂载位置、仅改变外层布局的放大方式；需要同时检查祖先裁剪、定位、页面占位与焦点。若必须移动或卸载，再明确需要保存的参数、相机、成形过程状态。不能先承诺“无损展开”，再把状态保存留给实现者补。

### 2.3 暂停动画、隐藏控件、禁止输入是三件事

代码确认：`TentacleBench` 的 `active` 控制 `useBenchLoop`，没有关闭单独注册的 wheel／pointer 监听；`SkinLayersTarget` 的 wheel 还会直接调用 `draw()`。`controls={false}` 只影响控件呈现，也不是通用输入开关。

修订：增加输入策略时必须改实际监听入口，不能只关动画或在外层罩一层。原先四处滚轮接线都要核对。放大时背景不可操作，需显式暂停背景相关循环；后台任务是否停下还要按台架确认。整机原有的固定视角例外保留，不能因为它属于 3D 就开启滚轮。

### 2.4 现有锚点可复用，但不是现成的工作台路由

`LabIndex` 依据页面滚动位置选中目录；`planFromHash` 和 `LegacyLabHash` 当前主要在挂载时读取或转换哈希。它们没有自动处理“工作台内换实验—退出—浏览器后退—恢复参数”的完整状态链。

修订：第一版保留已有长页与深链含义，直接链接仍定位对应实验或编制。放大是一台实验的临时展示状态，首版不增加在放大层内切换全部实验的导航。点击恢复回到来源实验，处理布局变化后的滚动位置与焦点。正式原型仍须验证前进后退、带编制链接和关闭行为；保留路由不等于这些检查可以省略。

## 3. 修订后的具体交互

| 场景 | 建议规则 | 还要验证的边界 |
|---|---|---|
| 桌面普通浏览 | 滚轮经过画布仍滚页面；拖动、参数按钮可直接操作 | 拖关节、拖人、拖相机分别保持原语义 |
| 普通浏览需要缩放模型 | 支持缩放的台架提供 +／− 与视角归位 | 不给固定视角台架新增能力 |
| 点击“放大操作” | 当前台架扩大到主要视口；可缩放画布接管普通滚轮 | 要有清楚的“滚轮缩放”提示、恢复按钮与 Esc |
| 放大后的说明区 | 滚该区域，不滚背景、不缩放模型 | 边缘滚动、键盘可达性与焦点恢复 |
| 鼠标处于参数控件上 | 不转交相机 | 明确控件自身的滚轮行为，不能只测画布中央 |
| Ctrl／Cmd 及浏览器缩放 | 不全局劫持；模型另有明确按钮 | 触控板捏合可能走浏览器缩放，不能宣称跨设备完全一致 |
| 手机普通页 | 标题、短说明、画面优先；单指滑页 | 需真实触屏验证，当前共享 touch-action 规则必须重新核对 |
| 调整侧栏 | 收起、恢复、受限调宽；可点击和键盘操作 | 字号不变、重要控件可见、无横向溢出 |

普通滚轮在浏览页和放大态含义不同，仍是一种模式切换。它的代价并未消失，只是通过显式入口、空间变化与操作提示让边界可识别。若真实试用仍频繁误操作，可退回两种布局都用缩放按钮；无需为此推翻整体布局。

## 4. 对“现在不好看”的判断需要收紧

初版能支持“固定列、长说明和密集控件在争空间”，尚不能支持“换成三栏工作台后一定好看”。目前没有包含真实长文、完整控件和多视图的候选设计稿；宽度条形图只演示空间分配。

保留 Archivo、绿紫和发丝线有项目依据，但这不是视觉答案。下一轮应在同一组真实内容上比较至少两种层级：简洁的说明展开区，以及需要常驻说明的并置区。都让模型先进入视线；检查标题、正文、按钮、状态、纹理的相对权重。不能只拿空画框或一台简单四杆证明 17 台都适用。

复用限制针对内核与成熟交互，不限制必要的视觉重排。仍可以显著改变页面节奏、说明位置、控件对齐、间距和背景层级；无需把当前两层网格当成不可动的框架。

## 5. 进入开发前需要的最少证据

先做代表性原型：1-3 触手验证相机与展开连续性，2-5 圆筒环验证密集控件，2-6 多层验证多视图。随后补 1-1 拖关节、1-5 固定视角与 2-11 拖人，检验统一规则是否误伤例外。

验收重点：

1. 连续翻过多个 3D 台架，页面不中断、相机不误变；桌面无需放大即可完成基本试用。
2. 在 1366×768、1280×800 下，当前画面与主要操作可同时找到；完整详情不会挤掉必要控制。
3. 调参数和相机后展开、调宽、恢复，没有重挂载、重置或重复实例；成形任务与背景暂停按约定工作。
4. 390px 手机没有整页横向溢出，能够越过画布正常滑页；触控板滚动与捏合分别实测。
5. 键盘、点击调宽、目录恢复、退出焦点和新旧深链都可用。

这些尚未完成，所以本次结论是“修订方向可继续做原型”，不是“方案已经验证通过”。
