### 7.9 Lab.04 蒙皮改「可调遮罩 + 点阵织纹」（2026-07-29，用户两轮拍板）

**这是对稿的一处有意偏离**（§7.7 刚把「织物蒙皮」按稿补齐，本轮把它的**呈现方式**换掉）：稿内蒙皮是不透明烟灰实体面，实测在暗底上是一整片压过来的灰布——内部机构（十四板三角桁架、曲柄轮、脚槽）全被盖住，五环只剩两端轮廓露在外面（用户：「死灰一片，柔和一些」）。第一版换成纯点阵，用户再纠偏「**别纯波点，加个滑块能调遮罩透明度**——可以变成不透明 / 半透明 / 全透明」。**几何来源与锚固点两轮都一字未改**（仍是相邻环外侧支点等弧长重采样出的直纹带），换的只是这张带子怎么画。

**同一张带子出两层，共用一个 0–1 滑块**：

| 层 | 数据 | α | 作用 |
|---|---|---|---|
| 遮罩面 | 三角面（`SKIN_SAMPLES` 41 列重采样 + `bakeIndexed`） | = 滑块值 | 壳体的「面」，滑到 1 即实体 |
| 点阵织纹 | 格心点云（`SKIN_U` 58 × `SKIN_V` 11，`bakeRuledPoints`） | `min(0.72, 滑块×1.8)` | 织纹质感，滑块刚离 0 就到位 ⇒ 低透明度读作纱、不是空 |

- **点阵取格心不取等分端点**：`v=0/1` 正落在两侧折线上，相邻两带会在共用的那条环线上叠出双倍密度、还与线稿重影。
- **两层都吃族系配色**：点色沿带宽从 A 环色渐到 B 环色；遮罩面取两环色中值压到稿内烟灰的明度区间（`dark=mid×0.13` / `lite=mid×0.62`）——亮度照旧（不透明时仍是沉下去的壳），但带上色相，这是「不再死灰」的主因。
- **点的形体交给不透明度、颜色只轻微压暗**（`rgb×(0.74+0.26λ)`、`α=A×(0.3+0.7λ)`）：暗底上若照实体面那样再乘明暗，背光的点会压成灰渣——实测第一版就是这毛病。
- **点径是世界单位**（`SKIN_DOT_R` 1.75mm，着色器里 `/w` 做透视缩放、clamp 到 1–14px）：缩放时点跟着变大，密度观感恒定；透视开关下近大远小自然成立。
- **半透明的三条硬约束**：① **深度只测不写**——否则一张 α=0.2 的面照样把后面的东西挡光（"半透明"名存实亡），但仍被先画的实体正确挡住；② 因此**绘制序反过来**：实体线稿先画，遮罩与点阵最后画（要与已成像的线稿混合）；③ 半透明面之间没有 z 排序，四条带须**按视深从远到近**自己排（`bandsFarToNear`，取两环轮毂中点、`q.z = 视矩阵第三行·(p−pivot)`，越大越近）。
- **α ≥ `SKIN_OPAQUE_AT`(0.985) 切实体路径**：写深度、在线稿之前画，遮挡交回 z-buffer 精确给出（不再依赖那个带级排序，避免带自身在掠射角下的自重叠出错）。
- **控件：滑块取代原「蒙皮」复选框**（中文标 `遮罩`、英文 `Skin`，侧栏带 % 读数）。开关的两端就是滑轨的两端，并存会出现「蒙皮开着但透明度 0」这种自相矛盾的状态。默认 `SKIN_DEFAULT` 0.35（半透明纱）。
- 手感常量 `SKIN_SAMPLES / SKIN_U / SKIN_V / SKIN_DOT_R / SKIN_DEFAULT / dotAlpha 增益` 全在 `RingsBench.tsx` 顶部，**待用户真机拍板**。

**装备侧仍是加法式扩展**：`gl3d` 新增 `drawPointCloud` + 纯函数 `bakeRuledPoints`（新程序 `POINT_VS/FS`），`drawDynamicMesh` 加可选 `alpha`（半透明路径：开混合 + `depthMask(false)`，画完即还原），`MESH_FS` 加 `uAlpha` 但 `beginFrame` 每帧置 1 ⇒ **实体绘制路径逐像素不变**。canvas 是 premultipliedAlpha 的透明底，两处混合都必须走 `blendFuncSeparate(SRC_ALPHA, 1−SRC_ALPHA, ONE, 1−SRC_ALPHA)`，否则叠花底色。既有 `drawMesh/drawSkinned/drawLines/drawDots` 一行未改。

### 9.2 转场第二段：变位缩放（`components/site/PageEnter.tsx`）

原落地段是「不透明平面盖场 → `clipPath` 从满屏收回到 hero」——**裁出来的**，不是飞过去的。现改为真正的共享元素变位缩放：

**直飞（用户拍板 2026-07-27：「不要中间放大一下再缩小过去，能不能直接过去」）**——首版是「卡片位放大铺满 → 跳页 → 从满屏缩回 hero」，两段各自连续、合起来却是一次没有必要的鼓胀。现在 `/work/*` 走**一次飞行**：goPT 不再放大克隆，把它**钉在卡片原位**跳页，目标页量到 hero 后一次飞过去。`PageEnter` 那侧一行没为此改——它的起点一律取「克隆此刻的视觉框」，所以出发段是钉住还是放大，落地段不必知道。其余路由（`/archive` `/lab`）没有落点可飞，仍是稿内的生长铺满。
- **背景从预览块展开（用户拍板 2026-07-27：「现在是直接一下闪过来的，不太自然」）**：换页那一帧必须被盖住，但**怎么盖**是有讲究的——首版是一块全屏遮罩淡入，读起来是平白多出一层东西糊在脸上。改成底板从**预览块自己的框**沿四边铺开（`clip-path: inset()` 从源块矩形展到 `inset(0)`，`EXPAND_MS` 380，铺满即 push），读起来是这块预览的底板长成了新页面的背景。**用 clip 不用 scale**：缩放会把渐变一起拉伸变形，clip 只是把同一块底板露出来。底色取源块自身的 `backgroundImage`，取不到（活台架的包裹层没有底色）才退 `PT_BG`。展开期间预览块钉在原位、在底板之上（z 200 > 199）。铺满前 push 会从没盖住的边角漏出浅底主页硬切成深色案例页那一帧。
- **遮罩落地后要淡出、且压到 hero 之下**（`z-index` 100）：生长那条路遮罩被满屏克隆盖着，撤不撤都一样；直飞这条路它正盖着整页。若让它夹在 hero（150）与克隆（200）之间，活件被蒙一层灰而克隆不受影响，交叉淡出就成了「亮的淡成暗的」。

两段合一后的构件：

- **同一条几何路径，两个元素一起走**：出场克隆（body 上、跨路由存活的 `[data-pt-morph]`）与本页 hero 各自算「起点盒 → hero 版式盒」的 translate+scale，途中交叉淡出（`CROSSFADE` 0.55 处克隆已透明，活件接手）。几何在 `src/lib/site/flip.ts`（纯函数 + 9 项测试）：等比按宽 + 中心对齐 ⇒ 两个起点盒不同、终点盒相同的元素**全程重合**，看不出中途换了元素。实测两者中心 y 全程同值（1440×900：克隆 -14,-290,1469,1479 / hero -14,-96,1469,1091，中心均 449.5）。
- **起点取克隆此刻的视觉框**，不重新按视口算——上一段的末帧就是这一段的首帧，接缝为零（直飞下即卡片原位）。没有克隆时（窄视口无面板、或克隆源尺寸不足的兜底路径）才退回按视口 cover 算一帧，hero 自己缩回去，同样不露底。
- **着陆平面不再承担揭开**：`.pt-veil` 那条老路**原样保留**给没有 `data-pt-target` 的路由（`/archive` `/lab`）；有落点的路由上，遮罩只负责盖住换页那一帧然后淡出。白屏没有落脚点——hero 自身的渐变底 + `.ground-plane` 双重兜底。
- **z-index 只有 150**：克隆在 body 上 z=200，必须压在 hero 之上（交叉淡出要的就是这个前后关系）；150 足够压住 nav 与正文（都不带 z-index）。**周边内容揭入时跳过 hero 所在的那一块**——给它加 `filter` 会另起层叠上下文，把 hero 关进去、压回 nav 底下。
- **收尾连动画一起收**：硬兜底超时只复原内联样式、放任动画跑完，会让 hero 在失去 z-index 之后继续放大着压在正文底下（慢机器上先到超时，CDP 实测可见）。`finish` 里 `heroAnim.cancel()`。

### 9.3 克隆的画面：canvas 快照（`components/lab/snapshot.ts`）

`cloneNode(true)` **不复制 canvas 像素**——3D 台架当预览时，点下去机构凭空消失、只剩深色方块放大（§7.6 末尾那句「可接受」在主图也变成活件之后不再可接受：现在两端都是同一台机器，中间断一下最刺眼）。

## 11. 案例页中英切换（2026-07-28，用户拍板「和 log 页面同样的中英文切换滑块，以后每个项目的详情页也都这样」）

### 12.3 默认机位按**实测运动包络**重定（不是按静止一帧）

用户「把初始视角往左上挪一点，确保任何时候都全部在画内」。旧值 `pivot(−150,0,40) / scale 0.78` 实测下缘边距 **0px**（贴边，等于已经在裁）、右 21px，而左 121 上 134 全空着——画面整体偏右下。

做法：先把 scale 缩到不裁的比例，按 **60s**（覆盖待机摆动 15s 与舒卷 27s 两个周期）每 2s 采一帧、取包络并集，换算回视空间后解出「让包络居中」的枢轴。现值 `pivot(−158.02, 39.22, −24.37) / scale 0.75`，实测四边余量 **左 115 · 右 115 · 上 72 · 下 71**（画布 878×652 CSS px），全程无裁切。

**两个坑入档**：

1. **`cx` / `cy` 在 WebGL 台架上是死参数。** `gl3d` 只读 `matrix / pivotPoint / viewScale / pan`，屏幕中心恒取画布中心（`uHalf`）；`camera3d.project()` 那条 SVG 老路才用 `cx/cy`。第一版就是改 `cx/cy` 去挪画面——**scale 生效、位移毫无变化**，差点误判成「HMR 没热更」。要挪 WebGL 画面只能动 pivot（或 pan）。
2. **量包络前必须先藏 `.lab-hud`。** HUD 是压在画布上的 DOM 浮层，φ / apex 读数逐帧变，会被逐像素 diff 当成「形体」——表现为右下角边距恒定被吃满（右 21 / 下 17），怎么调机位都不动。加一条 `.lab-hud{display:none}` 才量到真东西。

三个数（pivot / scale / 蒙皮默认）仍是手感常量，待用户真机拍板（整机 spec M4）。

## 13. 转场保留台架工作状态 + 详情页操作面板重排（2026-07-29，用户拍板）

### 13.1 「点进详情页时图的工作状态要保留」

用户：「主页预览的图，在转场到项目详情的时候，它的工作状态要保留，不受影响地继续展示，而不是现在这样刷新了一下」。

主页预览位与案例页主图位是同一台台架（§12.1），但 SPA 换页时前者卸载、后者从头挂载——新实例从 θ₀ 起步、触手笔直、待机摆动重新缓入 6.5s。§9 那套转场把两端接得再准，落地这一下机器「倒带」了，读作刷新。

**做法是状态交接，不是保活**（`components/lab/handoff.ts`）。不把 canvas 抬到路由树外——那要一套持久门户，牵动 SSR / 布局 / z-index / 尺寸切换，代价远超收益。改为出场的实例把机构此刻的**位形**留在一个模块级单槽里，入场的实例照着摆好再继续跑。交接的是「机器现在长什么样」，不是组件实例。

交接内容：五环各自的节点坐标 + 曲柄角、触手节点坐标 + 三腱收缩率 + 待机时钟 + 运转/摆向/转速。

- **位形直接摆上去，不能「设个 θ 让它自己解过去」**：同一个 θ 有不止一个合法解（07-17 S3 坍缩就是这么来的），重解未必回到原来那支。
- 五环是拟静力学（只有 iterate、没有 Verlet 历史），`setNode` 摆上即可。
- 触手是动力学件，**两次 `setNode` 夹一个空步**：`setNode` 只改位置、不动 Verlet 的上一步位置 px，只摆位置的话第一个子步会算出 v =（目标位 − 笔直位）× damping 的巨大速度把臂甩飞（damping 0.992，甩出去很久才停）。px 是在每个子步**开头**从 x 拷过来的，所以「摆好 → 走恰好一个子步 → 再摆一遍」之后 px 与 x 都停在目标位。dt 取 1/120 = 恰好一个子步（fixed-step 的浮点护栏保证不多不少）。**内核零改**。
- **状态在快照那一刻留**（`setSnapshot` 的闭包里），不是卸载时：快照像素与状态必须是同一个瞬间，否则中间还隔着底板铺开的 380ms，落地的活件会比飞过来的快照超前一截，交叉淡出就成了「跳一下」。

**三个坑，都不报错、都只表现为「功能像没写」：**

1. **取状态必须在挂载流程最前面取。** `createMachine()` 里有五环的脚槽止程标定（每环扫 360 步 × 四档余量），开发模式下要跑好几秒。第一版写在用到的地方才取，实测取到时 age 已 7.1s，被保质期挡掉。
2. **取走后要留一小段宽限期。** React 严格模式下开发期每个组件挂两次（挂→卸→再挂），**留下的是第二个实例**；取走即彻底清掉，恢复恰好落在被丢弃的那一个上——线上没事、开发期永远看不到效果。宽限期内重复取回同一份即可（数据只读）。
3. **保质期本身要有。** 留了状态却没换成页（用户按了返回、转场被打断），下次挂载不该套用一份陈的。

守门测试 `components/lab/handoff.test.ts`（7 项）就卡这三条。统计条 249 → **256**。

**验证方法也踩了一次坑**：本环境是软件 GL 且主页同时挂着五台台架，帧率极低，而每帧 dt 封顶 50ms ⇒ 仿真只跑到真实速度的约 1/7。所以「悬停 6.6s 再点」得到的源状态其实只推进了 0.8s，落地看着像重新开始。真正的判据是**捕获值与落地首帧相等**：capture 记下 θ=0.9308（= φ 36.7°）、三腱 0.093，落地首读 φ 36.7°、三腱 9/9/9 —— 逐位对上。

### 13.2 详情页操作面板重排（不再被截断）

用户：「详情页的操作面板也得改好点，现在这个被截断了，不行，重新排版」。

Lab.05 有八组控件，§ 侧栏那套竖排一列量到 **939px**，而案例页主图的高度被首屏预算封在 356–449px（`.case-hero--live` 的 `max-height` + `overflow:hidden`），多出来的只能靠 `.lab-ctl` 的 `overflow-y` 滚——等于看不见。

改法：

- **两列网格 + `align-content: space-between`**。这一列的高度不是常数，等于 `min(画面按比例的高, 100svh − 首屏预算)`：1366×768 只有 356px、1440×1000 有 449px。所以「排得下」不能按一个视口调——压到最矮视口也装得下，高视口多出来的空间摊到行距里，底下不留空白。
- 前四组（驱动 / 转速 / 相位 / 蒙皮）各占半格，后四组通栏——它们组内要横铺（部件四个复选框、三腱三根滑杆、单环六个按钮、视角五个按钮），半格挤不开。DOM 顺序据此调过（**蒙皮提到相位之后**），让四个半格连成两行。
- **通栏那几组的组名收到行首**，不再独占一行：三个标签行就是 54px，正是最矮视口差的那一截。
- 侧栏模式不出操作提示那行字（控件已全摆在眼前，只占 45px）。
- 列宽 188 → **272px**：hero 的 `max-width` 是「画面宽 + 控制列宽」，但案例页正文列把整件封在 868px，所以控制列每宽 1px 画面就窄 1px。320px 时画面掉到 546、272px 时 594（原 640）；再窄则分段按钮开始挤字。

**两个坑：**

1. **量「有没有被裁」要拿 hero 盒当参照，不是控制列自己。** `overflow:hidden` 在 hero 那一层；拿控制列当参照，列比 hero 高时一律报「没超出」——正好瞎在用户看到的那个 bug 上，第一版就是这么误判过关的。
2. **复选框要 `flex: none`。** 四格一行时每格只剩 ~48px，字撑不动，压的就是那个 11px 方框——四个部件复选框全挤成 `|` 号。

实测（CDP，六档视口 × 中英两侧）：1366×768 / 1280×800 / 1440×1000 / 1680×912 / 1920×1080 / 2560×1300 全部无裁切、无内滚、主图仍在首屏。`/lab` 的横排控制条一行未改（改的全在 `.lab-wrap--side` 作用域内）。

## 23. /lab 两栏对齐：台架框不拉伸 + 左栏框内滚（2026-08-31 / 09-01）

`.lab-section` 是两列 grid，行高由更长的那一栏定。两条都是用户看真机指出来的：

- **台架框不再被拉满行高**（`alignSelf: start`）。左栏比台架长时，`stretch` 会把那个
  带边框的盒子拉成一个空框，框线一路画到底下什么也没有——Lab.14 实测空了 614px，
  Lab.10 / 12 各 132 / 110px。
- **左栏改成框内滚**（`.lab-copy` / `.lab-copy__inner`）。内容用 `position:absolute;
  inset:0` 抽出文档流 ⇒ **行高只由台架那栏定**，左栏再长也不撑高这一行；两栏因此
  永远等高、底边齐平。窄屏（<1024px）单列下整段规则不生效——那时左右变成上下两块，
  限高滚动只会更难读（实测 900px 下 `position:static / overflow:visible`）。
- **「下面还有」的提示不能只靠滚动条**：macOS 与 headless Chromium 都是 overlay 滚动条，
  静置时根本不画（本轮截图实测看不见），读者会以为规格表只有两行。渐隐又必须条件化——
  内容没超出时挂一层渐隐会把规格表末行的发丝线糊掉，而纯 CSS 做不到这个条件
  （sticky 在内容短时照样贴底，`animation-timeline: scroll()` 兼容性还不稳）。
  故加最小客户端组件 `components/lab/LabCopyScroll.tsx`：只在还能往下滚时给
  `.lab-copy` 挂 `data-more`，滚到底自动摘掉；样式仍全在 globals.css
