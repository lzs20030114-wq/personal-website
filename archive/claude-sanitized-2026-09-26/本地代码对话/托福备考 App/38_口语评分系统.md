> ## 二、三个真正的缺口（建议围绕这三件事建设）
>
> **1. 没有评分锚点 —— 这是最要命的。** `data/realExam2026/speaking` 里只有题目本体（51套跟读+14套采访），grep 全目录**零命中**任何评分标准/样例作答/分数样本。写作评分大修之所以能收官，靠的是官方判分锚 v3；口语没有这个东西，所以现在 interview 的 0-5 分本质上是 DeepSeek 的自由心证——改一次 prompt 分数就可能整体漂移，而且没人知道漂了。
>
> **2. Interview 链路成熟度远低于写作。** 写作有三路采样取中位（抗边界抖动）+ marker 段落协议 + calibration 规则护栏 + 防退化门直跑生产本体；interview 只有单采样 + 极简 JSON parse + clamp。写作评分踩过的坑（4/5 边界方差大、推理 token 饿死正文）口语一个都还没防。
>
> **3. 声学信号已经买了却没用。** transcribe 路由特意开了 `verbose_json + word 级时间戳`，注释自陈"留给未来 fluency/pacing 评分"，但前端从未消费 `words` 字段。也就是说：**语速、停顿分布、有效说话时长这些真实声学测量，数据已经在每次返回里白白带回来了**，而现在的"Fluency"分是 LLM 看转写文本瞎猜的。
>
> ## 三、分期实施计划（建议按此顺序）
>
> **Phase 0 · 自建评分锚点集（golden set）— 一切的前提**
> - 既然真题没有作答样本，就自建：给 bank 里 8-10 套 interview 题，用 AI 生成分级作答样本（0-1分跑题/碎片、2分勉强、3分基本完整、4分良好、5分流利充分），每档 3-5 份，人工快速审核定级。
> - 这个集合就是口语版的"判分锚"：评分器的回归测试基准。没有它，后面所有 prompt 调整都是盲改。
> - Repeat 侧顺带做一个转写噪声鲁棒性用例集（同音词、数字写法、缩略语 normalize——LCS 对 "it's/it is"、"20/twenty" 这类目前会误判扣分）。
>
> **Phase 1 · Interview 评分对齐写作成熟度 — 性价比最高**
> - 三路采样取中位：`callAIMulti(samples=3)` 现成，写作已验证服务端 fan-out 只扣用户 1 次额度，直接复用。
> - 加 calibration 护栏层：作答词数下限硬顶分、跑题硬检测、转写长度 vs 录音时长比异常检测（防空录音高分）。
> - 用 Phase 0 锚点集验收：中枢分、档位序错率达标才算完成。
> - 成本：每场 interview 从 4 次 DeepSeek 调用变 12 次，DeepSeek 单价下仍是分厘级，写作已验证过同款模式。
>
> **Phase 2 · 接入 Whisper 词级时间戳 — 零 API 成本的差异化能力**
> - 从 `words` 时间戳算客观指标：语速 wpm、停顿次数/时长分布、有效说话占比、填充词率。
> - Interview：把这些硬测量作为 Fluency 维度的事实输入喂给 LLM（"该生语速 92wpm，3 次 >2s 停顿"），取代文本瞎猜。
> - Repeat：加语速合理性信号，并让逐词对比更准。
> - 这一步不多花一分钱（数据已在返回里），却是和竞品拉开差距的点。
>
> **Phase 3 · 防退化门 + band 口径统一**
> - 照写作 `scoring-gate.mjs` 的模式建口语评分门：每次改评分 prompt，自动跑 Phase 0 锚点集，中枢/序错率不许退化，锁死。
> - 顺手清债：band/CEFR 映射三处重复实现抽成公共函数（adaptiveScoring / bandScore / SpeakingExamShell 各有一份，阈值将来必漂移）；删除已死的 `speechRecognition.js`（Web Speech API 国内不可用已弃用）。
>
> **Phase 4 · 音素级发音评估 — 建议后置**
> - 真发音打分（重音/连读/音素错误）需要专门服务（如 Azure Pronunciation Assessment），按量付费、接入成本高。建议等 Phase 1-2 上线后看用户反馈再决定，不要现在做。

>        PronScore     85    ← 加权总分
