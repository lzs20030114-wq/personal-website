# 作品集具体项目｜我可以在这个项目中尝试机器学习吗？

### 用户

> 我可以在这个项目中尝试机器学习吗？

### 用户

> 你先去了解我的这个建筑尺度的身体交互作品集项目，问题是：我可以在这个项目中尝试机器学习吗？

### 助手

> 能，而且 ML 本来就在我们之前列的那张"计算从哪进来"的单子上——所以它是个正经选项，不是我现编的。但"我能不能用机器学习"这个问法偏了半寸。真正该问的是：**我的问题需不需要它，还是我在伸手够它、因为它听起来该出现在计算设计作品集里。** 后者正是这几轮一直在绕开的坑（技术撑场、论点缺席）。先把这把尺子立着，再说具体哪儿能用、哪儿会反伤。
>
> **真正能嵌进来的地方——在你已经选的"空间适应身体 + 随时间"里,最干净的入口是强化学习（RL）当 agent 的"大脑"。**
>
> - 累积型里那个**贪心的身体**（每步走向当前最优可供性），这条手写规则完全可以升级成一个**学出来的策略**——agent 自己学怎么"住"，而不是被一条 if 推着走。
> - 多人社会版（①②③）是 RL 最名正言顺的地方：agent 不再按"靠近+对视=想连接"这种死规则动，而是**学**出开合边界的社交行为。涌现就从"我编的规则跑出来的"升级成"它自己学会的"——论点更重，也更贴近这个领域现在真在做的事。
>
> **会反伤你的地方——别拿 ML 去做可供性模型本身。**
>
> 那套手写判据（450mm 能坐之类）是你**智识严谨度的展台**，是评审一眼读懂你在想什么的那一层。换成训练出来的黑箱，你省了写规则，却把项目最该透明的地方变成"它说能坐就能坐"。计算设计评审读逻辑极快，**可读性是硬通货**，这里上 ML 是净亏。同理用 GAN/扩散去"生成"排布也别碰：离散组合系统用聚合/CA/语法又透明又对口，套生成模型是拿大锤砸钉子、还砸碎了可解释性。
>
> **对你的处境，裁决是：错的第一步，对的第二阶段。**
>
> RL 是盖在一摞你还没搭的地基上的（神经网络、训练循环……），而且出了名地难调——奖励设歪，agent 就钻空子跑出一堆抽风行为；吃样本、难 debug。对一个零基础、卡着申请线的人当**起手**，几乎注定陷在调参泥潭里发不了车。但它是个特别自然的**延伸**，和我们一直说的 A→B 同一条弧线。触发点也干净：**先把规则版引擎跑起来，等那个贪心身体／死规则 agent 让你觉得"太蠢、不够"的那一刻,就是一个学出来的策略真正挣到位置的时候。** 那时它是被问题逼出来的，不是焊上去的——这俩在作品集里读起来天差地别。
>
> 最后关于"该不该有"：ML 确实越来越是这个领域的中心，作品集里能说"我用了学出来的策略"是加分的——但加分来自它**被问题驱动**，不来自它存在本身。焊上去的 ML 读作新手用力过猛；长出来的 ML 读作成熟。
>
> 所以真正的岔路：**是一个需要"学习"的问题在拽你，还是"机器学习"这四个字在拽你？** 如果是前者，我可以把那个学出来的策略具体落到你选的方向里（输入什么、学什么、第一个能跑的小版本长啥样），让"以后能加"从一句安慰变成你看得见的东西。

### 用户

> 机器学习一般被用来解决什么问题？

### 助手

> 一句话抓住本质：**机器学习是用来对付那种"你写不出规则、但手里有例子"的问题。** 传统编程是你把规则写好、电脑照着执行；ML 反过来——你喂例子，电脑自己把规则找出来。所以判断要不要用它就这一刀：这个问题的规则，我能不能自己写清楚？能，就别用；写不出但有数据，它才上场。
>
> 按"你在问什么"分，主要就这几类：
>
> - **这是 X 还是 Y？（分类 classification）** 给一堆带标签的例子，学会给新东西归类。垃圾邮件/正常、肿瘤良性/恶性、图里是猫是狗。
> - **多少 / 几个？（回归 regression）** 预测一个连续数值。房价、明天气温、点击率。
> - **这堆东西里藏着哪些群？（聚类 clustering）** 没有标签，让它自己发现数据里的自然分组。用户分群、把一万个空间按相似度归堆。
> - **我该一步步怎么做才能赢？（强化学习 RL）** 通过反复试错、追逐奖励，学会一连串决策。下棋、机器人走路、游戏 AI——也就是上一轮说的"让 agent 学会怎么住、怎么社交"。
> - **再给我造一些这样的。（生成模型）** 把数据的结构学到家，然后产出新的。ChatGPT、图像生成，本质都是这一类。
>
> 串起来的那根线：**全是"规则太复杂或太模糊、人手写不出来，但你有例子（或一个能反复试的环境）"** 的场景。
>
> 反过来，三种情况 ML 不是答案，对你尤其要记：
>
> - **规则你能写清楚**——别拿神经网络去做一个计算器。你那个可供性模型就属于这种，判据写得出，上 ML 反而退步。
> - **数据不够**——ML 吃数据，没有足够例子它学不出东西。
> - **你需要知道"为什么"**——很多 ML 是黑箱，给答案但说不清理由；要可解释、要替它向评审讲逻辑的地方，黑箱是负分。
>
> 放回你的项目就一句话：**能手写规则的核（可供性判据）→ 不碰 ML；说不清的"好行为"（agent 怎么住、怎么社交）→ 才是 RL 的地盘。** 这把尺子你拿稳了，以后每遇到一个"要不要上 ML"，先问"规则我写得出来吗"，基本就有答案了。

### 用户

> 机器学习的技术栈，你用简单语言跟我介绍 我具体是用什么工具跑？

### 助手

> 好消息先说：**ML 的技术栈几乎全是 Python**——一门语言通吃，而且它也正好是最适合你的第一门语言。所以"用什么写"这个问题答案就一个：Python，没有岔路。
>
> **你具体在哪儿"跑"（这是你问的重点）：**
>
> - **新手最好的起点是 Google Colab。** 它就是开在浏览器里的一个代码本，什么都不用装，免费，还白送你一块 GPU（跑 ML 要用的芯片）。你把代码写进一个个"格子"，一格一格运行，结果立刻显示在下面。
> - Colab 底层是 **Jupyter Notebook**——"代码 + 结果 + 笔记"穿插在一起的那种文件（后缀 .ipynb）。这是数据/ML 圈干活和展示的标准形态，做作品集也好用，能把你的思考过程一并摆出来。
> - 以后想在自己电脑上跑，再上 **VS Code**（一个编辑器），把 Python 装好、写本地脚本或 notebook。但在自己电脑上把环境弄顺是最烦人的一段——所以**先在 Colab 起步，本地化以后再说**。
>
> **库（工具包），按用途分三层：**
>
> - **数据层（干啥都要用）：** NumPy（数组和数学，地基）、pandas（在代码里处理表格、读 CSV、清洗）、Matplotlib（画图、把数据和结果可视化）。
> - **经典 ML 层：** **scikit-learn** 一个就够——分类、回归、聚类（上一轮那张表里的东西）全在里面，接口统一、专为新手。只要不是深度神经网络，就用它。
> - **深度学习层：** **PyTorch**（现在研究界主流、最直觉，推荐学这个）；TensorFlow/Keras 是另一大家，认得名字就行。神经网络、RL、生成模型——scikit-learn 扛不动时才上这层。（RL 还会在 PyTorch 上再叠一层专门的库，比如 Gymnasium + Stable-Baselines3，但那是后话。）
>
> **最关键的一句，给你现在：** 你那个 v0（离散网格 + 聚合 + 可供性读取器）**根本还不是机器学习**，它就是纯 Python——格子、循环、条件、函数，加 NumPy、加画图。所以现在你要装、要学的，是**核心 Python + NumPy + 一个画图工具**，连 scikit-learn 都未必用得上，PyTorch 更是八字没一撇。深度学习那层是第二阶段的工具，等你真走到我们说的那个"学出来的策略"再碰——跟上一轮 ML 的排序一个道理：别提前给自己上重装备。
>
> 落地一句：**打开 Colab，先把 Python 和 NumPy/pandas 啃熟，这就是你这周能动手的全部。** 要我把"零基础第一周到底学什么、做什么"列成一个具体小清单吗？
