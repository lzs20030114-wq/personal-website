> ## 核心内容板块
>
> **首页 / Hero** —— 一句话定位 + 你的核心张力。环艺出身但转向计算设计,这个"跨界"是你最大的卖点,首页就要立住。比如"用空间设计的思维做计算,用代码重新理解环境"这类。配一两个最强项目的视觉。
>
> **About** —— 不要写成简历。讲清楚一条叙事线:为什么从环境艺术走向计算设计?中间发生了什么让你想学代码?招生官最想看到的是动机的连贯性,而不是你做过多少事。
>
> **Work / Projects** —— 网站的主体。每个项目单独成页,而不是只放图。计算设计的项目页应该包含:问题定义 → 你的方法/思路 → 过程(草图、迭代、代码片段、参数化逻辑) → 结果。**过程比成品重要**,这是计算设计审美和纯效果图审美的根本区别。
>
> **Code / Experiments** —— 单独开一块放你的学习产物。哪怕是很小的东西(一个 generative art 的小 demo、一个数据可视化、Grasshopper 脚本),都放进来。这块直接证明你"正在学且学得动",对转专业申请极其关键。
>
> **Contact** —— 邮箱、GitHub、可下载的简历/CV。
>

> ## 两个问题的判断
>
> **素材状态:** 既然记忆里没有,我先按最可能的情况假设——你大概率是"有环艺/效果图项目,但缺计算设计方向的作品"。这是清华美院环艺学生转计算设计时最典型的缺口。如果猜错了你纠正我。这意味着网站的内容策略不是"把已有作品摆上去",而是**一边搭网站一边补计算设计作品**,网站本身就是补的第一件。
>
> **搭建方式——我的建议:手写代码,但用一个轻量框架托底。**
>
> 理由很直接。你五五开的目标里,"学代码"占一半,而你申请的就是计算设计专业——如果用 Wix、Squarespace 这种拖拽模板,招生官一眼能看出来,反而暴露你不会写。但纯手写裸 HTML/CSS/JS 从零搭一个完整网站,对刚起步的你又太重,容易卡在工程问题上消耗掉学习热情。
>
> 折中方案是 **Astro + 部署到 Vercel/GitHub Pages**:
>
> - 它让你用接近原生的 HTML/CSS 写页面,学到的是真东西,不是被框架包起来的黑盒;
> - 内容用 Markdown 管理,你加一个新项目就是写一个 `.md` 文件,不用碰复杂逻辑;
> - 配合 GitHub 部署,你顺带把 **Git / GitHub 工作流**也练了——这恰恰是计算设计研究生入学时默认你会的基本功;
> - 整个网站的源码公开在你 GitHub 上,本身就是作品的一部分。
>
> 如果你想再往计算设计的审美靠,可以在某个页面嵌一个 **p5.js 或 Three.js 的小交互**(比如首页背景是一段 generative 的几何动画),这块既是练手也是展示,一举两得。
>
> ## 落地优先级(给你一条三步路线)
>
> **第一步——先上线一个最小版本。** 只做四页:首页、About、一个项目页(拿你最强的一个环艺项目)、Contact。目的是先跑通 Astro → GitHub → Vercel 整条链路,体验"代码变成线上网站"的完整闭环。这一步的成就感会带着你走下去。
>
> **第二步——补计算设计内容。** 开 Code/Experiments 板块,把你学代码过程中做的每个小东西放进去。哪怕第一个只是"用 p5.js 画了 100 个随机圆",也放。这块是你转专业叙事的核心证据,要持续更新。
>
> **第三步——深化项目页。** 回头把环艺项目重新讲一遍,强调里面隐含的计算/系统/参数化思维(环艺项目里其实经常有这种逻辑,只是以前没往这个方向讲)。
>
