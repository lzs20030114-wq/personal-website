### 用户

> 我现在想要用一个电池能够分别按顺序输出start和end点连接到别的地方 怎么做到？

### 助手

> 看你截图里的情况——你已经用了一个 **Curve → Start/End** 组件（End Points 电池），它会分别输出每条曲线的起点和终点。现在你想"用一个电池按顺序分别输出 Start 和 End"到不同的地方，有几种常见做法：
>
> ## 方法 1：直接用两根线（最简单）
>
> End Points 电池本身就已经把 Start 和 End 分成两个输出端口了。你只需要：
> - 从 **Start** 输出端拉一根线到你想要的地方 A
> - 从 **End** 输出端拉一根线到你想要的地方 B
>
> 如果你的意思就是"一个电池同时输出两种点"，**这就已经满足了**——End Points 就是这个电池。
>
> ## 方法 2：把 Start 和 End 合并成一个列表再按索引取用
>
> 如果你是想要 `[start0, end0, start1, end1, ...]` 这样交替的一个列表，可以：
>
> 1. 把 Start 和 End 都接到 **Merge** 电池（或者 **Entwine**）
> 2. 用 **Entwine** 的话，输出是树形结构 `{0}=starts, {1}=ends`，可以 **Flip Matrix** 后 **Flatten** 得到交替序列
> 3. 或者用 **Weave** + Pattern `{0,1}` 直接织成交替列表
>
> ## 方法 3：用 Explode 代替 End Points
>
> **Curve → Explode** 也能输出端点（Vertices 输出端），对于一条直线段和 End Points 效果一样，而且还能同时给你分段曲线。
>
> ---
>
> 问一下确认我理解对了——你说的"按顺序输出 Start 和 End 连接到别的地方"，是指：
>
> **(A)** 想让一个电池的两个输出分别去两个不同的目标（那方法 1 就是答案）
>
> 还是 
>
> **(B)** 想把所有起点和所有终点合并成一个按顺序排列的列表（那就是方法 2）
>
> 截图里你 End Points 下游接了一个看起来像 List Item 的电池（有 List/Index/Wrap 输入），所以我猜可能是 B——你想构造一个交替序列然后用 List Item 按索引取？如果是这样我可以帮你把 Merge/Weave 的具体接线说清楚。

> End Points.End   ──→ List Item (B) .List

>
> ## 什么是数据树
>
> 你可以把数据树想象成**带编号的文件夹系统**：
>
> ```
> 普通列表（Flat List）:
> [A, B, C, D, E]   ← 就是一条数据，5 个元素
>
> 数据树（Data Tree）:
> {0} → [A, B]      ← 0号文件夹里装了2个东西
> {1} → [C]         ← 1号文件夹里装了1个东西
> {2} → [D, E, F]   ← 2号文件夹里装了3个东西
> ```
>
> 每个"文件夹"有个路径（叫 **Path**），比如 `{0;1;2}`，里面装着一个列表。
>
> **GH 里的每根线，里面流动的都是数据树**——哪怕是普通列表，本质上也是只有一个分支 `{0}` 的树。
>
> ## 为什么需要数据树
>
> 因为你的需求就是它的典型场景——**"不规则映射关系"**。比如：
>
> - 30 条肌腱，每条要连不同数量的模块
> - 用普通列表没法表达"第 3 条连 2 个模块、第 4 条连 1 个模块"
> - 但用数据树就很自然：`{3}=[M2,M7], {4}=[M5]`
>
> ## 核心电池（按重要性排序）
>
> ### 🔧 1. Graft（嫁接）—— **最最常用**
> 把列表的每个元素放进独立的分支：
> ```
> 输入: [A, B, C]  (一个列表)
> 输出: {0}=[A], {1}=[B], {2}=[C]  (三个分支，每个一个元素)
> ```
> **用途**：让每个数据"独立"起来，不跟其他数据纠缠。
> **图标**：小树苗图标
>
> ### 🔧 2. Flatten（压平）—— **第二常用**
> 把树压成一个普通列表，所有分支合并：
> ```
> 输入: {0}=[A,B], {1}=[C,D]
> 输出: [A, B, C, D]
> ```
> **用途**：当你不想要树结构了，想回到简单列表。
>
> ### 🔧 3. Entwine（编织成树）
> 把多个输入合并成一棵树，每个输入一个分支：
> ```
> 输入1: A    → 分支 {0}=[A]
> 输入2: B,C  → 分支 {1}=[B,C]
> 输入3: D    → 分支 {2}=[D]
> ```
> **用途**：手动构造树结构，是你这种"不规则映射"的关键电池。
>
> ### 🔧 4. Merge（合并）
> 把多个输入合并成一个**列表**（不是树）：
> ```
> 输入1: A
> 输入2: B,C
> 输入3: D
> 输出: [A, B, C, D]
> ```
> **用途**：简单合并，就是你已经在用的那个电池。
>
> ### 🔧 5. Tree Branch / Path Mapper
> 从树里按路径取东西。进阶用。
>
> ### 🔧 6. Param Viewer（参数查看器）—— **调试神器**
> 双击打开，能直观看到任何一根线的树结构：
> ```
> {0} N=3   ← 分支0 有3个元素
> {1} N=1   ← 分支1 有1个元素
> {2} N=5   ← 分支2 有5个元素
> ```
> **用途**：不确定数据结构长什么样的时候，接一个看看。你现在就可以去试试。
>
> ## GH 的配对规则（数据匹配 Data Matching）
>
> 这是关键——**两棵树怎么配对**决定了下游发生什么。
>
> ### 规则 1：两个列表 → 一一对应
> ```
> Start: [S0, S1, S2]
> End:   [E0, E1, E2]
> → 组件会做：(S0,E0), (S1,E1), (S2,E2)
> ```
>
> ### 规则 2：列表 + 单个值 → 重复那个值
> ```
> Points: [P0, P1, P2]
> Number: 5
> → (P0,5), (P1,5), (P2,5)
> ```
>
> ### 规则 3：两棵树 → 按路径配对
> ```
> 树A: {0}=[a], {1}=[b], {2}=[c]
> 树B: {0}=[1,2], {1}=[3], {2}=[4,5]
> → {0}: (a,1)(a,2)  {1}: (b,3)  {2}: (c,4)(c,5)
> ```
> **这就是你要的！**
>

>   - 有规律："肌腱 i 的 start 锁到模块 i，end 锁到模块 i+1" → 可以用数学计算自动生成索引
>   - 手动："我就是想肌腱3的start锁模块7，这是机械结构决定的" → 需要手动写索引表

### 用户

> 3组每组14个线 要链接到15个物体上 这三组每一组都是相同的连法，规则是：比如，第一条线起点锁在第一个块儿上 终点锁在第二个块 第二条线起点锁在第二个块 终点锁在第三个块 以此类推

### 助手

> 完美！**这就是最理想的情况——完全有规律的映射**。数据树配合几个简单电池就能搞定，不用任何手动索引表。
>
> ## 规律梳理
>
> - 14 条线 × 3 组 = 42 条
> - 15 个模块
> - 第 i 条线：**start 锁模块 i，end 锁模块 i+1**
>
> 所以每个模块收到的点：
> ```
> 模块 0: 线0.start
> 模块 1: 线0.end, 线1.start
> 模块 2: 线1.end, 线2.start
> ...
> 模块 13: 线12.end, 线13.start
> 模块 14: 线13.end
> ```
>
> 中间 13 个模块每个收 2 个点（一条线的终点 + 下一条线的起点），头尾各收 1 个点。**标准的链式结构。**
>
> ## 先处理一组（14 条线 + 15 个模块）
>
> ### 思路
>
> 用 **Shift List**（列表偏移）电池，把 End 列表往后挪一位，就自然实现了 start 和 end 的"错位对齐"。
>
> ```
> Start 列表: [S0, S1, S2, ..., S13]           ← 对应模块 0~13
> End   列表: [E0, E1, E2, ..., E13]           ← 对应模块 1~14
> ```
>
> 看，**Start 的第 i 个属于模块 i，End 的第 i 个属于模块 i+1**。
>
> ### 构造"每个模块接收的点"的树
>
> 用 **Entwine** 分成 15 个分支（每个分支一个模块）：
>
> ```
> 分支 {0}:  [Start[0]]              ← 模块0，只有1个点
> 分支 {1}:  [End[0], Start[1]]      ← 模块1，2个点
> 分支 {2}:  [End[1], Start[2]]      ← 模块2，2个点
> ...
> 分支 {13}: [End[12], Start[13]]    ← 模块13，2个点
> 分支 {14}: [End[13]]               ← 模块14，只有1个点
> ```
>
> ## 具体电池接法（推荐方案）
>
> ### 方法：Weave + Partition List（最优雅）
>
> **第 1 步**：把 Start 和 End 用 **Weave** 织成交替列表
>
> ```
> Start: [S0, S1, ..., S13]  ─┐
> End:   [E0, E1, ..., E13]  ─┼── Weave ──→ [S0, E0, S1, E1, S2, E2, ..., S13, E13]
> Pattern: 0,1                ─┘
> ```
>
> 得到一个长度 28 的交替列表。
>
> **第 2 步**：在头尾"补齐"，让中间的配对刚好
>
> 我们需要的分组是：
> ```
> {0}: [S0]
> {1}: [E0, S1]
> {2}: [E1, S2]
> ...
> {13}: [E12, S13]
> {14}: [E13]
> ```
>
> 观察 Weave 结果 `[S0, E0, S1, E1, S2, E2, ..., S13, E13]`：
>
> - 头上单独取 `S0` → 分支 {0}
> - 然后从 `E0` 开始，**每 2 个一组**配对 → 得到 (E0,S1)(E1,S2)...(E12,S13) 共 13 组 → 分支 {1}~{13}
> - 最后剩下 `E13` → 分支 {14}
>
> 用 **Partition List** 电池（或叫 Split List）把中间 26 个元素每 2 个一组分开。
>
> ### 更简单的方法：直接手动错位
>
> 其实最直观的做法是：
>
> **第 1 步**：准备两个列表
> ```
> Start 列表（graft 后）: {0}=S0, {1}=S1, ..., {13}=S13
> ```
>
> **第 2 步**：把 End 列表整体右移一位（索引 +1）
>
> 用 **Shift Paths**，或者更直接——构造 End 的 graft 树时让它从 {1} 开始：
>
> ```
> End 列表（graft + shift）: {1}=E0, {2}=E1, ..., {14}=E13
> ```
>
> **第 3 步**：用 **Merge** 合并这两棵树
>
> GH 会自动按路径合并相同分支：
> ```
> {0}:  [S0]                      (只有 Start 贡献)
> {1}:  [S1, E0]                  (两边都贡献)
> {2}:  [S2, E1]
> ...
> {13}: [S13, E12]
> {14}: [E13]                     (只有 End 贡献)
> ```
>
> **完美！这就是你要的树结构。**
>
> ## 完整接法
>
> ```
> [End Points]
>     ├─ Start ─→ [Graft] ────────────────────────────┐
>     │           (生成 {0}~{13} 的树)                │
>     │                                               ├─→ [Merge] ─→ 点树
>     └─ End   ─→ [Graft] ─→ [Shift Paths +1] ────────┘                │
>                 (生成 {1}~{14} 的树)                                  ↓
>                                                               RigidBody.Points
> ```
>
> **Shift Paths** 电池的参数：
> - Offset: `1`（把所有路径的最后一个索引 +1）
>
> 或者更简单，直接用 **Path Mapper** 写规则：`{A} → {A+1}`
>
> ## 关于 RigidBody 电池
>
> 你现在右边有 15 个独立的 RigidBody 电池对吧？**把它们也合并成 1 个**：
>
> ```
> 15个Brep ──→ Merge ──→ RigidBody.Part
> 15个Plane ─→ Merge ──→ RigidBody.Plane
> 点树     ───────────→ RigidBody.Points
> Strength ───────────→ RigidBody.Strength (一个值就够，会自动重复)
> ```
>
> **1 个 RigidBody 电池处理所有 15 个模块**。输出的刚体也是一个列表，直接接到 Kangaroo Solver。
>
> ## 三组怎么办
>
> 三组线完全独立？还是三组会共用同一批模块？
>
> ### 如果三组各自有各自的 15 个模块（完全独立）
>
> **做 3 遍相同的操作就行**——每组一套 End Points + Graft + Shift + Merge + RigidBody。或者把这套操作做成一个 **Cluster**（把电池组合打包成一个自定义电池），复制 3 份用。
>
> ### 如果三组共享同一批 15 个模块
>
> 那每个模块收到的点就更多了（来自 3 组线的贡献）。做法：
> - 3 组线各自做一遍 Graft + Shift，得到 3 棵树
> - 用 **Merge** 把 3 棵树合并
> - 相同路径的分支会自动合并内容
> - 最终每个模块（每个分支）收到 3×(1或2) 个点
>
