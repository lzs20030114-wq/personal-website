# 非项目对话｜在工作中使用jev

### 用户

> 综合我的工作 我可以如何使用jev？（指的是ai模型方面）

### 助手

> 我先查一下"jev"具体指什么，再结合你的工作来回答。
>
> Jev 是 TypeSafe AI 九月中刚发的模型，不生成文本，输入程序状态 + 一组带类型的问题，单次并行返回带概率的结构化答案。70–500ms，输入 $0.042/百万 token，输出免费。因为输出格式是你事先定死的，它没法胡编。
>
> 一句话理解：它不是"更小的 LLM"，它是一个**你可以在代码里当函数调用的判断器**，而且每次判断会告诉你自己有多确定。
>
> 结合你在做的事，按价值排序：
>
> **1. 多智能体模拟（人猫共居那个作品集项目）——最贴的一个**
>
> 这是 Jev 的原生场景。官方 demo 就是 Minecraft bot、无人机避障、类 Subway Surfers 游戏这种实时控制循环，两分钟 Minecraft 大约 1 美分，15 分钟无人机模拟大约 10 美分。
>
> 你的猫 agent 每一帧要决定"去窗台/躲开人/找水碗"，如果用 LLM 一帧一次调用，成本和延迟都不可能跑。Jev 可以：给它当前状态（人在哪、猫的饥饿值、声音强度），一次问十个问题，成本几乎不变（同一个请求里的所有问题是并行评估的，加问题几乎不增加响应时间）。
>
> 而且对作品集叙事有用：你能说"猫的行为不是我写的 if-else 规则，是一个有概率的判断层"，同时**置信度可以直接可视化**——猫犹豫的时候概率接近 50/50，这本身就是可以画出来的图像。
>
> **2. n8n 外包活**
>
> 你现在接的自动化单子里，凡是"这封邮件属于哪类""这个请求该走哪条分支"，现在大概是调一次 LLM 让它输出 JSON 再解析。换 Jev：更快更便宜，而且不用做 JSON 解析和校验的兜底代码。有开发者拿它替换 OpenAI 的分类器做命令安全审查，快了 5–18 倍且准确率更高；另一个测试里 Gemini 稍微准一点但贵 10–20 倍。
>
> 更实用的是**置信度分流**：置信度 >0.9 自动执行，0.6–0.9 走 旧助手 复核，<0.6 推给人。这比"LLM 说啥就是啥"专业得多，也是你能跟客户讲清楚的卖点。
>
> **3. 错题本 / 作业识别**
>
> 分类任务密集：题目属于哪个知识点、难度几级、这步是不是算错了。用 Jev 先判，低置信度的题目才调大模型详细讲解。省钱之外更重要的是——**你有了一个可量化的"该不该让人复核"的依据**，做教育产品这点很关键，判错题的代价很高。
>
> **4. 游戏开发 / Arduino 机械生物**
>
> NPC 或那个机械生物的"性格"决策层。同上，实时循环、低成本。
>
> **要说清楚的限制：**
>
> - 它**完全不写文本**。不能生成解释、句子、代码。你的阅读 app 里"解释这个词"还是得用 LLM，只有"这个词对该用户算不算难"适合 Jev。
> - 在 TypeSafe 自己的 benchmark 上 Jev 准确率 67.8%，和 GPT-5.6 Terra 差不多，比 Opus 5（73.1%）低几个点。而且评测是这家公司自己做的——别当成它更聪明，它是"够用但极快极便宜"。
> - 目前是早期访问，发布后需求太大一度 API 挂掉。别把作品集截止日前必须跑通的东西压在上面。
> - 所有可能的答案必须**事先定义**。它做不了开放式的"你觉得该干啥"。
>
> **给你的具体建议**
>
> 你的情况（自学代码、要申计算设计）最划算的切入点是 **人猫共居那个项目**。理由：它同时练到了状态设计（把空间和 agent 的情况编码成结构化输入，这就是计算设计的核心技能）、概率思维、以及一个可以写进作品集说明的技术选择理由。而且失败成本低——跑不通就退回规则系统，不影响项目主线。
>
> n8n 那边等你手上有下一单再顺手换，不用现在重构。
>
> 要不要我帮你把猫 agent 的状态和问题列表设计出来？那一步比写代码重要，也是能直接放进作品集的思考过程。
