# 非项目对话｜3xui登录页面无法跳转

### 用户

> [65.49.202.164]([已隐去url]):2053 这个现在是我新的vpn的3xui地址，但是我现在在普通浏览器上打开登录之后 无法跳转 一直卡在这个登录页 什么原因？

### 助手

> 这个「登录成功但一直卡在登录页」是 3X-UI 的经典问题，本质基本都是**会话 cookie 没有被保存或立即失效**。按可能性从高到低排查：
>
> **1. 面板配置了 HTTPS 证书，但你在用 http:// 访问**
>
> 如果你之前在面板里设置过 TLS 证书（哪怕是自签的），3X-UI 会把 session cookie 标记为 secure，HTTP 访问时浏览器拒绝保存 cookie → 登录后立刻被打回。试试改用 `[已隐去url] Chrome 自动把 http 升级成了 https 而面板没配证书，也会出问题——留意地址栏实际协议。
>
> **2. 服务器时间不对**
>
> 3X-UI 的 session 有时效校验，VPS 时钟偏差大会导致 session 生成即过期。SSH 上去：
>
> ```bash
> date
> timedatectl set-ntp true
> ```
>
> 看时间和北京时间/UTC 是否对得上，不对就同步后重启面板 `x-ui restart`。
>
> **3. 你正挂着代理访问面板**
>
> 如果你当前浏览器流量走的是旧代理或系统 VPN，出口 IP 可能在请求之间变化，3X-UI 会判定 session 无效。直连（关掉代理）访问面板试一次。
>
> **4. 浏览器本身**
>
> 无痕窗口 + 关闭所有扩展试一次，排除 cookie 拦截类插件。
>
> **快速定位方法**：F12 打开开发者工具 → Network 面板 → 点登录 → 看 `login` 请求的响应。如果返回 `success: true` 但页面不跳转，就是 cookie 问题（对应 1/3/4）；如果返回失败或超时，才是密码/后端问题。也可以看 Application → Cookies 里登录后有没有出现 `3x-ui` 相关的 cookie。
>
> 另外确认一下 webBasePath：SSH 里跑 `x-ui settings`,看有没有设置过路径。如果设置过（比如 `/abc123/`），你必须访问 `[已隐去url] 才是真正的入口——不过一般路径错会 404 而不是卡登录页,所以这个可能性较低。
>
> 先从第 1 和第 2 条查起，命中率最高。

### 用户

> 但是我用无痕浏览就ok

### 助手

> 那就锁定了：问题在你普通浏览器的**本地状态**，不是服务器。无痕模式 = 干净的 cookie + 禁用扩展，它能登录说明服务器端一切正常。
>
> 具体是这两种之一：
>
> **最可能：残留的旧 cookie 冲突**
>
> 你之前的 3X-UI（旧 VPS 或迁移前的洛杉矶机器)如果用过同一个 IP:端口组合，或浏览器里存着同名的过期 session cookie，新面板登录时旧 cookie 一起被发送，服务端校验失败就把你踢回登录页。
>
> 解决：不用清空全部浏览记录，只清这个站点的——
>
> Chrome 地址栏访问该面板页面 → 点地址栏左侧的图标（锁或「不安全」）→ **网站设置** → **删除数据**；或者 `chrome://settings/siteData` 里搜 `65.49.202.164` 删掉。然后重新登录。
>
> **次可能：某个扩展在拦截**
>
> 无痕默认禁用扩展。如果清了 cookie 还不行,就是某个扩展（隐私类、cookie 管理类、去广告类，比如 uBlock、Privacy Badger、SwitchyOmega 的某条规则）在拦截这个裸 IP 站点的 cookie。逐个禁用排查，或者干脆给这个 IP 加白名单。
>
> 顺带一提：SwitchyOmega 值得单独检查——如果你的代理规则里有匹配到这个 IP 的条目，普通窗口走代理、无痕窗口直连，也会出现「无痕正常、普通不行」的现象。
>
> 清 cookie 大概率一步解决。
