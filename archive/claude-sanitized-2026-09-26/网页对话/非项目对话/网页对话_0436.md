# 非项目对话｜防回归的定义和含义

### 用户

> 防回归是什么

### 助手

> **防回归**(anti-regression / 防止回归)是软件开发里的概念,核心意思是:**防止本来已经正常工作的功能,在你改了代码之后又坏掉。**
>
> 这里的"回归"(regression)指的就是功能"倒退"——比如你给 treepractice.com 加了个新特性,结果不小心把原来好好的登录功能弄崩了,这就叫一次 regression。代码状态"回退"到了有 bug 的样子。
>
> 之所以会发生,是因为软件一大,各部分会互相牵连。你改 A 处,可能意外影响到看似无关的 B 处;而且功能多了之后,人脑根本记不住每次改动会波及哪些地方。
>
> 防回归就是为此搭的一张"安全网",主要靠几样东西:
>
> **回归测试**是最基础的——把已有功能都写成测试用例,每次改完代码就重新跑一遍,确认旧功能还在正常工作。
>
> **自动化测试 + CI**(持续集成)是工程化的做法。你把单元测试、集成测试写好,挂到 GitHub Actions 这类 CI 上,每次 `git push` 或开 PR 时自动跑全套测试,红了就不让合并。这样你不用每次手动检查。
>
> 对你做 web 开发还有个特别相关的:**视觉回归测试**(visual regression testing),专门对比 UI 改动前后的渲染截图,防止你调了个样式结果把别的页面布局搞乱了。
>
> 对你现在的实际意义:等 treepractice.com 功能多起来,如果一直靠手动点页面来确认"没改坏",会越来越累且容易漏。早点写测试 + 配个 CI,就是给自己上保险——这也是从"会写代码"过渡到"能维护一个真实项目"的关键一步,放进研究生申请的技术叙事里也很加分。
>
> ---
>
> 如果你其实是在别的语境下看到这个词的(比如机器学习里防止模型微调后能力退化、或者康复训练里防止症状复发),跟我说一声,含义会不太一样。
