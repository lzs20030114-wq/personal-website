### 用户

> 我现在想要装一个小红书mcp，爬取托福工具同赛道宣传最好的帖子的话术学习，然后mcp自动编辑发帖

### 助手

> 先说结论：**学话术这件事值得做，但不建议用 MCP 自动跑你的主账号；"自动发帖"这一步建议直接放弃。**
>
> 技术上这类工具确实存在——GitHub 上 star 比较高的有 xpzouying/xiaohongshu-mcp、chenningling 的 RedBook-Search-Comment-MCP，本质都是用 Playwright 做浏览器自动化、模拟真人操作，能登录、搜关键词、抓笔记和评论、自动发帖。但对你这个具体情况有两个要命的问题：
>
> [已隐去账号相关描述]
>
> **二是就算侥幸不封，机器批量发的内容现在也跑不动量。** 这一版算法更偏向真实体验、细节拆解，而"全网最好用""效果最显著"这类绝对化表述会直接被限流、很难进推荐池。你本来"真实学生分享"的人设是优势，自动化反而会把这个优势抹掉。
>
> 你之前自己总结的合规线仍然成立：AI 辅助 + 50% 以上人工改写 + 主动声明。这句话的含义是——你需要的是一个**草稿助手**，不是一个**自动发布器**。
>
> 更稳的拆法是把整件事拆成三步，让 AI 只做合规且高杠杆的两步：
>
> 1. **采集**：手动存 20–30 篇赛道爆款；或者你想顺便练代码的话，写一个只读小爬虫，用小号或不登录、低频跑，纯收集研究数据——绝不碰主账号。
> 2. **分析**：把这批帖子丢给 旧助手 / DeepSeek，让它拆钩子、标题结构、收藏触发点、CTA 套路，提炼成可复用的模板。
> 3. **出稿 + 发布**：AI 出草稿 → 你按自己语气大改 → 手机手动发，并勾选 AI 声明。
>
> 这样自动化里真正值钱的部分（分析 + 出稿）你全拿到了，把风险最高的"自动发主账号"那一步去掉。
>
> 要不要我帮你：(a) 把那个只读研究爬虫当作你的第一个代码项目搭起来，还是 (b) 先把"分析竞品 → 出稿"这套提示词和流程做出来？

### 助手

> 爬虫这块直接用现成的就行，不用从零写。最对口的是 **MediaCrawler**(GitHub: NanmiCoder/MediaCrawler)——它用 Playwright 保留登录后的浏览器上下文、靠执行 JS 表达式拿到加密签名参数，省掉了逆向核心加密代码的麻烦，目前能抓小红书的笔记、评论、点赞、转发等信息，支持按关键词搜索抓取，正好用来批量收赛道爆款。项目本身定位成技术研究/学习工具，使用者需遵守相关法律、自负责任。
>
> 用它有几条纪律，都是为了护住你的主账号：
>
> - 登录一定用小号，别用过认证的主账号——它需要扫码/手机号/cookie 登录，自动化行为挂在哪个号上，风险就落在哪个号
> - 低频、只读、只采公开数据，别高并发猛刷，容易触发滑块验证
> - 它会随小红书改版而失效，属于需要时不时修的工具，不是一劳永逸
> - Python 版本有讲究（不同 fork 要求 3.7–3.9 不等），按它的 README 来；你在 Windows 上 `venv\Scripts\activate` 激活就行
>
> 至于用 Chrome 的 MCP 跑自动发帖——换了壳，风险没变。三月那条新规针对的是"行为类别"：AI 智能体模拟真人操作、自动发布笔记。OpenClaw（虾爪）被点名，恰恰因为它就是"agent 驱动浏览器自动发帖"。而 旧助手 in Chrome 驱动小红书发帖，正好落在这个类别本身。规则是按行为定义的，所以从专用 MCP 换成通用浏览器 agent，绕不过去——更何况挂的还是你那个主账号。你说的"未必"是对的，我支持这个判断：发布这一步留给人工。
>
> 下一步我可以帮你把 MediaCrawler 在 Windows 上跑起来（含踩坑），再写一个吃它导出的 CSV/JSON、自动拆解"标题钩子 / 收藏触发点 / CTA 套路"的分析脚本。"用别人造好的爬虫轮子 + 自己写分析层"其实是个很合适的第一个代码项目——精力花在能学到东西、又直接产出话术模板的那一层。要不要这么走？
